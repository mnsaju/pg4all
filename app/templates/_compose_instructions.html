{# Included after _credentials.html in result.html and credential.html. Expects `credential` (for build_id) plus `has_compose`/`has_pgbackrest`/ `has_pgadmin`/`has_grafana`/`pgadmin_email`/`grafana_user`/`host_ports` — computed by checking build_output// on disk, not stored on the credential record, since the build artifacts themselves are just as durable as the encrypted credential store. `host_ports` comes from the build's ports.json, so a build made before ports were configurable still shows the defaults it was actually given. #} {% if has_compose %}

Companion services were included in this build. Start Postgres and all of them together from the generated compose file:

cd build_output/{{ credential.build_id }} docker compose up -d
{% endif %} {% if has_pgadmin %}

pgAdmin is bound to 127.0.0.1 only on port {{ host_ports['pgadmin'] }} — it is never published to the network, so reach it over an SSH tunnel to the host, not directly:

ssh -L {{ host_ports['pgadmin'] }}:127.0.0.1:{{ host_ports['pgadmin'] }} <host> # then open http://localhost:{{ host_ports['pgadmin'] }} pgAdmin login: {{ pgadmin_email }} pgAdmin password: (same as the superuser password above)

Add the Postgres connection yourself the first time you open it — host postgres, port 5432, same username/password. That's the container-side port on the compose network, which doesn't change when you move the published host port. pg4all doesn't pre-seed it.

{% endif %} {% if has_grafana %}

Grafana is bound to 127.0.0.1 only on port {{ host_ports['grafana'] }}, like pgAdmin — reach it over an SSH tunnel:

ssh -L {{ host_ports['grafana'] }}:127.0.0.1:{{ host_ports['grafana'] }} <host> # then open http://localhost:{{ host_ports['grafana'] }} Grafana login: {{ grafana_user }} Grafana password: (same as the superuser password above)

The “pg4all — PostgreSQL” dashboard is already provisioned, with this build's own tuning values in it: connections are plotted against the max_connections you chose, checkpoints against your max_wal_size. Prometheus is on {{ host_ports['prometheus'] }}, also loopback-only — tunnel to it the same way if a panel is empty and you want to check the scrape target is up.

Metrics live in a named volume. docker compose down keeps them; docker compose down -v deletes the history along with the database. Prometheus keeps 15 days or 2 GB, whichever comes first.

{% endif %} {% if has_pgbackrest %}

pgBackRest is installed in the image with stanza main (/etc/pgbackrest/pgbackrest.conf). Mount a volume at /var/lib/pgbackrest for the backup repository, then run the stanza creation once and back up whenever you want — pg4all doesn't schedule this for you:

docker exec <container> pgbackrest --stanza=main stanza-create docker exec <container> pgbackrest --stanza=main backup
{% endif %}
